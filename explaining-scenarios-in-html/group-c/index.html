★ C1b：parse() 调用本身抛错、数据行从未被读——「读第一条记录之前报错」的现成先例

下游：放行时会发生什么——C2 的有损映射与 C3a 的空名 key
默认放行不等于「当作没发生」：C2 里 headerMap 被 :672 二次 put 覆盖（id→0 变 id→2），按名取值命中最后一个同名列（CSVRecord.java:108 Javadoc："only the last occurrence is returned"）；C3a 里空串被 put 成合法 key（""→1），get("") 完全可用。放行模式下 keySet 与物理列可以不一致——这是将来 required 校验必须意识到的形态。
→ C2 · 默认放行 + 后列覆盖 ｜ C3a · 空名 "" 也是 key
一句话版本：表头校验已存在两个时机——手工表头在 build 时、文件表头在 parse 时；后者天然早于任何数据记录，setRequiredHeaders 照此时机做即可（ch02-1-3 §1/§3）。

本组的核心维度：时机

  • 每张异常卡片都带 ⏱ 时机标注（build 期 / parse 期）——这是 C 组最重要的对照维度（ch02-1-2 踩坑 P5：重复表头校验有两个时机，最初只想到一个）；

  • c3b 页顶有「⟵ c3a 的 DISALLOW 对照」徽标，format 构建步浮出 🔀 diff 对比卡。
