① 先看总地图：三种表头来源，汇合到同一个 createHeaders()

来源 1：没有表头
format.header = null（如 CSVFormat.DEFAULT）
a1.csv：USD,100␍␊CNY,200␍␊
构造期不消费任何行；headerMap 保持 null（:632 不进入）
→ A1 · 下标取值可，按名取值抛 IllegalStateException
来源 2：文件自动探测
setHeader() 无参 → String[0]（长度 0 = 探测信号）
a2a.csv：id,currency,amount␍␊1,USD,100␍␊2,CNY,200␍␊
:635 命中 → :637 构造期吃掉首行 → :639 首行成为 headerRecord（skip 标志在此分支不起作用）
→ A2a · 文档推荐组合（skip=true）
→ A2b · 对照变体（不设 skip，行为相同）
来源 3：手工配置
setHeader("id",...) → 配置数组
a3.csv：1,USD,100␍␊2,CNY,200␍␊（无表头行）
a4.csv：id,currency,amount␍␊1,USD,100␍␊（自带表头行）
else 分支 → :649 headerRecord = 配置数组；:643-644 的 skip 是真开关（决定文件首行是否被消费）
→ A3 · 源无表头行
→ A4 · 文件自带表头 + skip=true
→ A4b · 对照变体（忘设 skip → 表头行混进数据）

汇合点：CSVParser.createHeaders()（CSVParser.java:628-683）
三种来源都到这里变成统一的表头世界：headerRecord + headerMap（名 → 下标）。现有的表头校验（空名 :658-659、重复名 :665-668）也在这里抛错——先于任何数据记录被读取。将来的 setRequiredHeaders 校验应放在汇合点之后（ch02-1-3 §3 候选②）。
↓
下游：惰性数据流 + 按名取值
构造完成后，CSVRecordIterator 逐行吐数据记录（records）；CSVRecord.get(String) 用 headerMap 查下标取值（:135 → :140），get(int) 纯数组下标（:104）。A1 证明无 headerMap 时按名取值抛 IllegalStateException（:132-133）。
一句话版本：表头校验有两个时机——手工表头在 builder.get()（build 时），文件表头在 format.parse()（parse 时）；而数据记录永远是惰性的，只会在构造完成之后才被读。（ch02-1-3 §1）

③ 阅读指南：怎么用这些交互页

步进操作

  • 底部按钮「◀ 上一步 / 下一步 ▶」，或键盘 ← / → / 空格；
  • 顶部一排圆点是全部步骤（颜色=阶段），点击可跳；
  • 点击测试代码的任意一行，直接跳到覆盖它的那一步；
  • 「自动播放」开关：约 6 秒/步，播完自动停；
  • URL 支持 ?step=N 直达任意步（0 起），例如 a1-….html?step=10。

画面分区

  • 左侧·测试代码：全部行从第 0 步就可见（先有地图），当前步覆盖的行高亮，行号 = 测试文件内真实行号；
  • 左侧下方·源码剧场：随步骤展开的源码摘录卡片（真实源码 + 行号），● 红点 = ch02-1-3 建议断点；
  • 右侧·四个面板：文件字节视图（紫色高亮当前被消费的行，\r\n 显式可见）→ 解析器状态（headerRecord / headerMap / records 随步生长）→ 变量监视盒 → 断言·异常·差异。

为什么每页都从"虚构的 CSV 文件"开始？

  • 6 个测试实际都用 new StringReader("…") 内联字符串喂数据，仓库里没有 .csv 文件；
  • 解析入口只认 Reader：format.parse(Reader)（CSVFormat.java:2207）与 CSVParser.parse(Path,…)（:407）汇合到同一构造器（:524），表头在构造期定案（:528）；
  • 所以"内联字符串"与"读文件"解析路径完全相同——每页第 0 步给出等价文件画面，第 1 步把这座桥讲透。
