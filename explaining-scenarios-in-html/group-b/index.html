旁路 1：isConsistent()（CSVRecord.java:237-239）—— 长短记录的沉默警报
headerMap.size() 与 values.length 的相等判定：B2a（3≠2）与 B2b（3≠4）都返回 false，但都不抛错——它是查询方法，不问不说。B2b 还证明"不一致"与"可读"可并存（get("amount")="100" 正常返回）。

一句话版本：隐性缺列（B2a）与显性缺名（B1）都只在取值时才炸——这正是需求要替换的"晚失败"。解析期永远安静；isConsistent() 是唯一的警报且默认沉默。

③ 阅读指南：怎么用这些交互页

步进操作

  • 底部按钮「◀ 上一步 / 下一步 ▶」，或键盘 ← / → / 空格；
  • 顶部一排圆点是全部步骤（颜色=阶段），点击可跳；
  • 点击测试代码的任意一行，直接跳到覆盖它的那一步；
  • 「自动播放」开关：约 6 秒/步，播完自动停；
  • URL 支持 ?step=N 直达任意步（0 起），例如 b1-….html?step=7。

画面分区

  • 左侧·测试代码：全部行从第 0 步就可见（先有地图），当前步覆盖的行高亮，行号 = 测试文件内真实行号；
  • 左侧下方·源码剧场：随步骤展开的源码摘录卡片（真实源码 + 行号），● 红点 = ch02-1-3 建议断点，灰色行 = 本场景走不到的分支；
  • 右侧·四个面板：文件字节视图（紫色高亮当前被消费的行，\r\n 显式可见）→ 解析器状态（headerRecord / headerMap / records 随步生长）→ 变量监视盒 → 断言·异常·差异。

为什么每页都从"虚构的 CSV 文件"开始？

  • 5 个测试实际都用 new StringReader("…") 内联字符串喂数据，仓库里没有 .csv 文件；
  • 解析入口只认 Reader：format.parse(Reader)（CSVFormat.java:2207）与 CSVParser.parse(Path,…)（:407）汇合到同一构造器（:524），表头在构造期定案（:528）；
  • 所以"内联字符串"与"读文件"解析路径完全相同——每页第 0 步给出等价文件画面，第 1 步把这座桥讲透。b3b 的空文件最直观：new StringReader("") 就是 0 字节文件的字符流。
