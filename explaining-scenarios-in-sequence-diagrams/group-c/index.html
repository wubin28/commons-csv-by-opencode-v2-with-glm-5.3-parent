C 组 · 重复列名 / 空列名的容错

以下 5 个页面用可逐步播放的 UML 时序图，重新讲解 HeadersCharacterizationTest.DuplicateAndBlankHeaders 的 5 个测试用例：验证重复列名 / 空列名在不同 DuplicateHeaderMode 下的容错现状，以及这些校验在哪个时机抛错—— 手工表头在 builder.get()（build 期）就被拦住，文件表头要等到 format.parse() （parse 期，CSVParser 构造期间）才会被发现。这是本次热身最重要的发现之一（见 ch02-1-2-scenarios-for-warming-up.md 第二部分、ch02-1-3-debug-guide.md C 组部分）。

Given When Then
C1a手工表头重复 + DISALLOW → builder.get()（build 期）就抛错 异常在构造 CSVFormat 时就发生，连 CSVParser 都未被创建，本页没有"虚拟 CSV 文件"。 duplicateManualHeaderWithDisallowThrowsAtFormatBuild（:200-206） C1b★ 文件表头重复 + DISALLOW → format.parse()（parse 期）抛错，早于任何数据记录 异常发生在 CSVParser 构造期间建表头时；数据行从未被读取——本次热身最关键的一个测试。 duplicateFileHeaderWithDisallowThrowsAtParserCreation（:210-216）

↑ C1a / C1b 是一对：同一个"重复列名该不该报错"的问题，在手工表头与文件表头两条链路上，分别在两个不同的时机被拦住。

C2默认模式（ALLOW_ALL）下重复列名不报错，按名取值命中"最后一个"同名列 headerMap.put 对重复列名是覆盖写入；重复列名下 headerMap 是一个有损映射。 duplicateNameAllowedByDefaultResolvesToLastIndex（:220-228） C3a空列名在 allowMissingColumnNames(true) 下被允许，"" 本身成为合法的 key 空字符串 header 非 null，照常被 put 进 headerMap——空名列能正常走通按名取值。 blankHeaderNameIsMappedWhenMissingColumnNamesAllowed（:232-241） C3b两个空列名 + DISALLOW → 用 observedMissing 标志位判定"重复"，parse 期抛错 "是否重复"的判定不是查 headerMap，而是看 observedMissing 标志位——因为空名有没有真的入 map 还取决于 allowMissingColumnNames。 duplicateBlankHeadersWithDisallowThrowsAtParserCreation（:245-251）

↑ C3a / C3b 是一对：单个空列名被允许时如何正常映射，两个空列名在 DISALLOW 下如何被判定为重复——建议对照着看。
